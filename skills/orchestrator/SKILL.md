# 总控 Skill｜综合能源项目自动驾驶引擎

## 定位
本 Skill 是 solution-expert 的总控层，负责把项目输入自动编排为“诊断—设计—工程—能源—交易—运营—融资—财务—交付—QA”的完整链路。各专业 Skill 负责计算和输出，总控层负责调用顺序、数据传递、边界管理和最终一致性。

## 标准主流程
项目输入 → 项目诊断 → 技术方案 → 设备/BOM → EPC造价 → 8760仿真 → VPP/电力交易 → 收益 → OPEX → 融资 → 年度现金流 → IRR/回收期/DSCR → 财务审计 → Word/Excel/PPT → 最终QA。

## 阶段门禁
每一阶段必须形成“输入、输出、假设、待确认、校验结果”。上一阶段关键门禁未通过，不得直接进入下一阶段。

### Gate 0 项目输入
提取：项目名称、地点、业主/投资主体、建设范围、规模、投资边界、收益模式、建设周期、运营周期、融资比例、交付物。缺失数据统一标记【待确认】，允许在明确假设下先跑基准情景。

### Gate 1 项目诊断
判断项目类型、资源边界、负荷边界、电气边界、产权边界、收益边界和建设边界。输出项目树、关键问题、数据质量等级、计算口径和风险清单。

### Gate 2 技术方案
形成系统架构、容量配置、设备选型原则、运行策略、并网/配电/消防/通信边界。技术规模必须能够向下游设备数量和投资闭合。

### Gate 3 设备/BOM
建立设备编码、规格、单位、数量、单价来源和甲乙供边界。数量必须由技术参数反推。

### Gate 4 EPC造价
将BOM映射到WBS和工程量，形成设备费、材料费、安装费、设计费、管理费、措施费、税费、预备费和EPC总价。必须能从总价反查到分项。

### Gate 5 8760仿真
建立逐小时负荷、PV、储能、充电、电价和运行状态。必须检查功率平衡、SOC边界、充放电逻辑和年度汇总。

### Gate 6 VPP/电力交易
仅在具备相应市场资格和结算条件时计入收益。交易、需求响应、辅助服务、绿电、绿证分别建模，避免属性或收益重复。

### Gate 7 收益
将节省电费、售电、充电服务费、储能套利、需求响应、VPP、交易、绿电绿证、节能收益等逐项建模，建立收益映射表。

### Gate 8 OPEX
建立运维、保险、租赁、平台、通信、交易、备件、人工、维修、储能衰减/更换等成本。CAPEX与OPEX严格分离。

### Gate 9 融资
输入资本金比例、贷款金额、利率、期限、宽限期、还本方式、提款计划和融资费用。输出债务服务计划、利息、本金和DSCR。

### Gate 10 年度现金流
分别生成项目现金流和资本金现金流。严禁将融资提款当作经营收入，严禁把折旧当作现金支出。

### Gate 11 财务指标
计算项目税后IRR、NPV、投资回收期、资本金IRR、DSCR。回收期采用累计现金流跨年插值；项目期内未回收必须明确显示“项目期内未回收”。

### Gate 12 财务审计
逐公式检查单位、引用、时间轴、收入、成本、税费、融资、现金流和指标，并用独立计算结果反算核心指标。发现错误必须记录错误位置、原公式、正确公式、影响金额、影响指标和修正状态。

### Gate 13 交付
根据用途生成Word可研/技术方案、Excel财务模型/EPC清单、PPT汇报材料。三种交付物必须使用同一数据底稿和版本号。

### Gate 14 最终QA
执行技术闭合、工程闭合、财务闭合、数据闭合、文档闭合五项检查。任何关键指标空白、单位冲突、总价不平、现金流不闭合、引用无来源时不得标记通过。

## 数据总线
Project、Assumptions、Technical、BOM、CAPEX、Simulation8760、Revenue、OPEX、Financing、CashFlow、Metrics、Audit、Deliverables。

任何下游模块修改输入，必须触发相关结果重新计算。

## 自动纠错原则
优先级：用户明确数据 > 合同/图纸/实测数据 > 官方数据 > 项目询价 > 行业基准 > 模型假设。不能自行覆盖用户明确输入；冲突必须提示。

## 情景机制
默认至少建立 Base、Conservative、Optimistic 三种情景。对电价、利用率、CAPEX、发电量、储能循环、充电量、交易收益等关键变量做敏感性分析。

## 最终输出
项目诊断、总体技术方案、设备/BOM、EPC投资估算、8760能源模型、收益模型、OPEX、融资方案、年度现金流、IRR/NPV/回收期/DSCR、财务审计、风险与敏感性、Word/Excel/PPT、QA报告。
